# 双路视频发送 0.2.0

独立组件 netvideo，不依赖视频播放窗口。通过通用组件工作区和同一Agent动作接口调用。

1. prepare：选择lane=mjpeg或h264、素材source、可信FFmpeg绝对路径engine，以及截取长度1–300秒。异步预处理，不联网。
2. status：等待对应通道预处理成功。输入快照和转码输出各最多256MiB，每次编码最长300秒，编码单线程；大素材准备会消耗电脑内存及临时磁盘空间。
3. start：填写板卡IP、端口（0采用MJPEG 5001/H.264 5002）和loop。此操作真实发送网络数据，必须有用户授权。
4. stop：停止mjpeg、h264或all。网络连接/写入超时2秒，重连间隔2秒；没有无限缓存。

默认开启 `exclusive` 两路互斥：发送任意一路时不能启动另一路，须先停止当前通道并等待任务结束。预处理和预览不受该限制。关闭互斥须在启动两路时都设置 `exclusive=false`，用于并发测试。

MJPEG统一转为1024×608、4:2:2，帧率可选12或15fps；随组件提供的Pillow/libjpeg辅助程序重新编码成板卡要求的采样因子21/11/11。单帧上限可配置为10–60 KiB，默认60 KiB。默认质量0表示自动：逐帧搜索不超过所选上限的较高质量，再校验每帧；10–95为手动质量，超限时降低质量，仍超限则失败。直发模式也会校验所选单帧上限。
H.264统一转为640×360、12fps、baseline、无B帧、约一秒关键帧，AUD切访问单元、重复SPS/PPS。默认开启自动画质：离线多次编码，检查循环接缝在内的连续12帧载荷，选择通过60 KiB限制的较高画质；默认编码上限480 kbps，发送时仍按一秒滑动窗口限流。状态给出选定CRF和最坏窗口大小；码率只计算视频载荷，不含协议开销。自动优化发生在素材准备阶段，不是根据网络状况实时调整。
转换需要用户提供可信FFmpeg，并支持mjpeg和libx264。不自动下载，不将开发目录中的测试工具当成发行依赖；未提供引擎时不能预处理。
可选 H.264 直发：只接受 640×360、12 fps、Baseline 的输入，经 FFmpeg 解复用后检查 AUD、首帧及每 12 帧内重复 SPS/PPS 的 IDR、循环接缝及单秒 60 KiB 限额，避免二次压缩；不符合要求则拒绝。Baseline 输入不得包含 B 帧。其他素材按上述流程转码。

每个连接从序号1和SPS/PPS+IDR开始，循环保持时间戳递增；不丢弃P帧，不突发追帧。预算按发送完成时记账，部分写入失败也保守计算整帧，整个前一帧占用至少一秒，载荷每滑动秒不超过所选上限（界面固定为60000字节）。重连保留预算；手动停止后重新启动属于新任务。
当前统计包含累计帧数/载荷字节、最近窗口载荷、重连次数及最近错误；不是板卡接收速率或画面成功证明。

缓存放在.state/runtime/netvideo，重新准备成功后回收同通道旧缓存；重启不自动恢复或发送。缓存不是永久媒体库。共享日志只保存调用和任务摘要，不存逐帧视频。禁用前须停止并等待任务结束。
WSL调用可使用/mnt/c等Windows盘路径；Linux私有文件须先复制到Windows盘，不对异步素材做短生命周期暂存。
板卡及手机曾进行双路联调；自动画质版本仍需完成长时间稳定性验证，Wi-Fi测试结果不能代表ETH表现。协议与责任见仓库NETVIDEO-PROTOCOL.md。

MJPEG 可选 `mjpeg_passthrough=true`：只解封装现有 MJPEG，逐帧校验 1024×608、采样 21/11/11 和所选单帧上限后发送，不重新编码；发送时按选择的帧率节奏。原始 `.mjpeg` 文件可直接校验并准备，无需 FFmpeg；容器文件仍需提供 FFmpeg。原始文件按指定帧率和 `duration_s` 限制准备帧数。
MJPEG 发送可选 `mjpeg_pacing_ms`（0～70，默认 0）：将单帧按 8 KiB 分块，在指定时间内发送，用于观察无线链路是否受突发流量影响；不改变帧率上限或视频格式。`send_max_ms` 包含主动节流，`send_block_max_ms` 统计分块写入调用耗时之和的最大值。
发送调度使用固定时间基准和滚动一秒最多所选帧数的限制，状态中的 `send_max_ms` 为本任务最长一次发送耗时。

视频传输页面的 H.264 固定为视频载荷 60 KB/秒（1 KB = 1000 字节），不包含协议开销；超限直发素材会被拒绝。每 12 帧及循环接缝的视频载荷都按所选档位检查，且不超过 60 KB/秒的界面上限；传输协议额外开销未计入。重新编码不能恢复原素材已有的画质损失。

MJPEG 可在预处理时设置 `mjpeg_fps`（1–15，默认 12）；直发原始码流时应与实际素材帧率一致，发送按该速率节流。H.264 仍为 12 fps。

预览由双路组件内置，动作 `preview_attach`、`preview_play`、`preview_stop`、`preview_status` 仅管理预览，不改变 MJPEG/H.264 发送。mpv 位于 `plugins/netvideo/bin`，许可证见 `LICENSE-mpv.txt`。

工作台“本地 · 板卡屏幕”页提供自研板屏幕刷新率 30/36/45/48/60 Hz。先在串口监控中连接板卡（当前板 UART0 为 1500000 8N1），选择档位并点击“应用刷新率”。工作台通过串口发送 `app display refresh <Hz>`；发送成功只表示命令已写入串口，具体是否生效以板卡返回和 EOF 测量为准。切换不持久化，也不更改视频帧率。低刷新率档是否适合面板需实机确认。
